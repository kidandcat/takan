# Takan OSS self-host audit

Audit of [github.com/kidandcat/takan](https://github.com/kidandcat/takan) plus the production hub on this host (`/opt/takan`, `takan.es`). Goal: anyone can run **their own** Takan the way Hairok runs it — not a multi-tenant SaaS Hairok operates for strangers.

**Date:** 2026-08-21 (snapshot of `master` @ `0f2df2b`; packaging implemented on `feat/oss-selfhost`)  
**Superseded auth model:** PR #5 (`feat/single-operator`, merged 2026-08-22) removed register/invites. The product is one operator + instance password. See [TAKAN_SINGLE_OPERATOR.md](TAKAN_SINGLE_OPERATOR.md). Sections below that still mention household invites describe the **pre-#5** tree.  
**Method:** read the public repo (clone at `/home/debian/takan`, `master` @ `0f2df2b`) and the live unit/env/SQLite on this VPS. No invented modules. No production deploy from this work.

**Verdict:** Takan is already a personal MCP hub with MIT, a single static Go binary, SQLite, and systemd. It is **not** a billing/onboarding SaaS. The gap for a stranger is packaging and defaults (Docker one-liner, `takan.es` hardcoded in examples and the agent, Colmena has no LICENSE file). There is **no hosted-SaaS product layer to delete**. After #5, do **not** bring back register/invites; `user_id` isolation stays as a storage key for the owner row.

This PR implements the P0 packaging/docs defaults. It does **not** restart or replace `/opt/takan`.

## 1. What is already fine for self-host

| Piece | Reality in tree / on this VPS |
|--------|-------------------------------|
| **License** | Repo is public. Root `LICENSE` is MIT (commit `d3056c2`, 2026-07-21). GitHub `licenseInfo.key = mit`. |
| **One binary** | `cmd/takan` is the hub (panel + MCP + OAuth + REST + agent WS + `/install.sh`). `CGO_ENABLED=0` works (`modernc.org/sqlite`). |
| **Agent** | `cmd/takan-agent` is a second static binary. Hub serves `/install.sh` and `/download/takan-agent-<os>-<arch>`. |
| **Env config** | `internal/config/config.go` — listen, public URL, data dir, session key, register flag, invite quota, OAuth extras, rate limits, optional S3. No compiled-in Hairok account. |
| **systemd** | `deploy/takan.service` plus live `/etc/systemd/system/takan.service` (`User=debian`, `ExecStart=/opt/takan/takan`, `EnvironmentFile=/etc/takan/takan.env`). Agent unit generated by install script. |
| **SQLite / Colmena** | Local files under `TAKAN_DATA_DIR` (`default.db`). S3 backup is optional and **off** in production (no `TAKAN_BACKUP_*` / AWS keys in `takan.env`). |
| **Bootstrap** | First registered user becomes admin + unlimited invites (`store.CreateUserOpts`). Later users need an invite unless `TAKAN_ALLOW_REGISTER=true`. Production has the flag **false**. |
| **CI** | `.github/workflows/ci.yml` — `go vet`, `go test ./...`, build hub + agent. |
| **Security docs** | `SECURITY.md`, invite-only default, session-key warning, rate limits. |
| **Dev loop** | `go run ./cmd/takan` with `TAKAN_PUBLIC_URL` + `TAKAN_SESSION_KEY` (README / CONTRIBUTING). |
| **Health** | `GET /healthz` → `ok`. |

Live production shape (this VPS, 2026-08-21): binary `/opt/takan/takan`, data `/opt/takan/data`, listen `127.0.0.1:8096`, public URL `https://takan.es`, Caddy terminates TLS, `TAKAN_ALLOW_REGISTER=false`, `TAKAN_DEFAULT_INVITE_QUOTA=5`. SQLite: **4 users, 2 admins, 5 machines, 0 unused invites**. That is already a household hub, not a public signup product.

## 2. What is missing (or in the way)

Items below are the **pre-PR** snapshot. P0 packaging/docs in §4 are implemented on this branch (`feat/oss-selfhost`); Colmena LICENSE and GitHub Releases are not.

### Packaging

- **No Dockerfile, no `docker compose`.** A stranger cannot `git clone && docker compose up`. This is the largest product gap.
- **No release tags / GitHub Releases** (`gh release list` empty). Agent download on a self-hosted hub only works if the operator builds the four `takan-agent-*` binaries into `TAKAN_AGENT_BIN_DIR` (Hairok does this under `/opt/takan/agents`).
- **`dist/` binaries are untracked** (local build artifacts). `.gitignore` did not ignore `/dist/` before this PR.

### Docs / defaults aimed at Hairok’s host

- README “Self-hosting (production sketch)” is a **Go build + systemd** recipe, not a home one-liner.
- `deploy/takan.env.example` sets `TAKAN_PUBLIC_URL=https://takan.es`.
- `deploy/Caddyfile.snippet` is `takan.es, www.takan.es`.
- `deploy/takan.service` hardcodes `User=debian`, `Group=debian`, `/opt/takan`.
- `cmd/takan-agent` defaulted `--url` / `TAKAN_URL` to **`https://takan.es`**. A self-hoster who forgets `--url` would try to join Hairok’s hub. Production is safe (unit passes `TAKAN_URL`), but the default is the wrong product signal.
- Comments in `internal/config/config.go` and `internal/oauth/server.go` still say `https://takan.es`.

### Secrets / first-run

- Empty `TAKAN_SESSION_KEY` falls back to `dev-insecure-change-me` (`config.Load`). That key **encrypts vault / Mercadona / email / telegram / SIP**. Docker must persist a generated key on the data volume or a restart mangles ciphertext.
- No CLI `takan bootstrap` — not required: `/register` is open when `UserCount == 0` even if register is closed afterwards.

### Cloud dependencies (modules, not the hub)

None of these are required to boot the hub. They are BYO credentials in the panel:

| Module | External API | Self-host implication |
|--------|----------------|------------------------|
| Email | Resend (`api.resend.com`) | Operator’s own Resend key + domains. No self-hosted SMTP. |
| SIP | xAI Realtime `wss://api.x.ai/v1/realtime` | Operator’s own xAI key. |
| Telegram | Bot API | Operator’s bot token. |
| Mercadona | Unofficial `tienda.mercadona.es` + public Algolia app `7UZJKL1DJ0` | Breaks if Mercadona changes; keys are the SPA’s anonymous search keys (documented in README). |
| Backup | Colmena → S3-compatible | Optional. Off on takan.es today. |

The hub itself talks to the internet only when a module is enabled and configured.

### Legal / supply chain

- **`github.com/mentasystems/colmena` is public and fetchable** (`proxy.golang.org` has `v1.0.0`) but **has no `LICENSE` file** (`licenseInfo: null`). README already says Colmena is a separate project. Unlicensed Go code is a redistribution risk for a “clone and run” OSS product. Fix belongs in the Colmena repo (add MIT or Apache-2.0), not by vendoring silently.

### Public registration

- Code supports `TAKAN_ALLOW_REGISTER` (default **false**). Production is false.
- Landing still offers “Register with invite” when closed — correct for household, and for bootstrap (first user).
- **Do not turn on open signup** on a public IP. That flag is the only “SaaS onboarding” switch; it should stay off for self-host docs.

## 3. Multi-user / “SaaS” inventory

There is **no** Stripe, billing, plans, orgs, tenant-as-customer, marketplace, or Hairok-operated onboarding funnel in this repo. What exists is a **single process, single SQLite file, many `user_id` rows**.

| Mechanism | Where | Keep / drop | Why |
|-----------|--------|-------------|-----|
| `users.is_admin` | `internal/store` | **Keep** | First user is admin; panel `/dashboard/admin` for household. |
| Invites + quota | `store/invites.go`, panel, `GET/POST /api/v1/invites` | **Keep** | Family/guests. Default quota 5 is a bit “viral”; admins can set 0. |
| `TAKAN_ALLOW_REGISTER` | config, web, oauth login link | **Keep flag, default false** | Needed for tests and the rare LAN-open box. Not a hosted product. |
| Per-user isolation | Every module table is `user_id` + FK. Tests in `tenant_test.go`, `vault_test.go` | **Keep** | Without this, a household invite leaks vault/health/machines. |
| OAuth public client `takan` | `internal/oauth` (`PublicClientID`, PKCE, DCR stub `POST /oauth/register`) | **Keep** | MCP clients (Grok/Claude/Cursor) require this. DCR always returns the same public client — not an app store. |
| Redirect allowlist | `oauth/redirect.go` (grok.com, x.ai, claude.ai, cursor, localhost) + `TAKAN_OAUTH_REDIRECT_ALLOW` | **Keep** | Safety, not multi-tenant SaaS. |
| Mobile REST `/api/v1` | `internal/api` (`clientMobile = takan-app`) | **Keep** | Companion app; optional. Login only (no public API register). |
| Rate limits | `TAKAN_AUTH_PER_MIN`, `TAKAN_MACHINE_BASH_PER_MIN` | **Keep** | Useful on a home public reverse proxy. |
| Landing marketing | `templates/home.html` | **Keep** | Local hub home page, not a hosted signup funnel. GitHub link is correct. |
| Mercadona `accounts` package comments “hosted multi-tenant” | `modules/mercadona/accounts` | **Keep code**, wording is leftover | Same DB, `account_id` = Takan `user_id`. Not a second product. |
| `mcp_tokens` table | created in `store.migrate`, **zero Go readers/writers** | Leave in DB | Dead schema. Dropping it is a migration; not SaaS. Do not touch on takan.es. |
| Billing / orgs / SSO IdP / usage meters | — | **N/A** | Not in the tree. |

**SaaS-shaped but correct for “admin + household”:**

- Isolation tests (`TestCrossTenantIsolation`) — required so guest B cannot read admin A’s people/health/vault/machines.
- Invite quota on **every** new user (default 5) — guests can invite further guests. For a stricter home: set `TAKAN_DEFAULT_INVITE_QUOTA=0` and only let the admin (unlimited) mint codes. Do **not** change the code default in a way that surprises takan.es (`TAKAN_DEFAULT_INVITE_QUOTA=5` is set in prod env).

**OAuth `POST /oauth/register`:** RFC 7591 dynamic client registration expected by MCP clients. It does **not** create Takan user accounts.

## 4. Prioritized work (stranger path)

Target path: clone → `docker compose up` → browser sets the instance password → panel creates a machine → `install.sh` on a PC → paste `https://<host>/mcp` into an AI client.

### P0 — this PR (non-destructive)

1. **Dockerfile + `docker-compose.yml` + entrypoint** that generates/persists `TAKAN_SESSION_KEY` on the data volume, listens on `0.0.0.0:8090`, ships linux/darwin agent binaries for `/install.sh`.
2. **README one-liner** (compose first; systemd second).
3. **Stop defaulting the agent to `takan.es`** (`--url` / `TAKAN_URL` required). Prod agent unit already sets `TAKAN_URL`.
4. **Generic `deploy/` examples** (`takan.example.com`, `User=takan`, S3-compatible backup comments).
5. **Warn** if the hub is using `dev-insecure-change-me`.
6. **This audit file.**

### P1 — next, still safe for takan.es

1. **LICENSE on Colmena** (`mentasystems/colmena`) — blocker for cautious redistributors.
2. **GitHub Release** with hub + four agent binaries (so systemd users skip local Go).
3. **Document LAN vs localhost `TAKAN_PUBLIC_URL`** (OAuth/MCP and `/install.sh` must advertise the URL clients actually use). Already started in README; worth a screenshot-level guide later.
4. Optional: default **guest** invite quota to 0 in *docs* (keep env default 5 on takan.es).
5. Compose recipe for Caddy/Tailscale TLS (second service profile), not in the default one-liner.

### P2 — product polish, not blockers

1. SMTP module or Resend-or-SMTP so email is not a cloud-only module.
2. Drop or migrate unused `mcp_tokens`.
3. Windows agent (not in current `dist/` naming).
4. `takan bootstrap --email --password` for headless first admin (nice; web register already works).
5. Refuse to start in “production” without `TAKAN_SESSION_KEY` (behavior change — do not flip on takan.es without checking env; prod **has** a key).

### P3 — do not do

1. **Do not remove** invites, `is_admin`, or `user_id` isolation.
2. **Do not enable** `TAKAN_ALLOW_REGISTER` on takan.es.
3. **Do not rewrite SQLite** or Colmena on the live data dir.
4. **Do not** add Stripe/orgs/“teams as customers”.

### Stranger checklist (after this PR)

```bash
git clone https://github.com/kidandcat/takan.git
cd takan
docker compose up --build
# open http://localhost:8090  → set the instance password
# Panel → Machines → create → curl -fsSL http://localhost:8090/install.sh | bash -s -- <token>
# AI client MCP URL: http://localhost:8090/mcp
```

## 5. Production constraints (takan.es)

| Action | Allowed from this work? |
|--------|-------------------------|
| Edit GitHub on a branch / PR | Yes |
| Merge docs + compose | Yes (operator must still merge) |
| Change live `/opt/takan/takan`, systemd, Caddy, SQLite | **No** |
| Flip `TAKAN_ALLOW_REGISTER` | **No** |
| Schema drop (`mcp_tokens`, etc.) | **No** |

Live listen port is **8096**, repo examples use **8090**. Caddy on this host proxies `takan.es` → `127.0.0.1:8096`. Keep that drift local; do not “fix” production to match the example.

Agent cmdline on this VPS includes the raw token (`ps` shows `--token …`). That is an operator hygiene issue (env file is already `0600`); not changed here.

## 7. What this PR does **not** remove (on purpose)

Open self-signup **code** stays behind the env flag. Invites stay. OAuth DCR stays. Admin user list stays. Calling those “SaaS” would break the household product and, if shipped to takan.es, the four existing accounts.

## 8. MCP events / Grok Bot wakeup (see TAKAN_EVENTS.md)

Takan already pushes two JSON-RPC notifications on GET `/mcp` SSE: `notifications/takan/machine_ai_job` (agent `ai_done`) and `notifications/tools/list_changed` (module/tool config). Email, Mercadona, Telegram, display, SIP, vault grants are **poll tools**, not pushes. Grok Bot **holds** that SSE stream on `takan.es` but **does not start a new turn** on the custom job notification (Grok Build only handles `tools/list_changed` / `resources/list_changed` as UI status). Idle Minerva will not notice a finished machine grok unless the same turn called `machine_ai_watch`, or we add an out-of-band wake (Grok Automations webhook / Telegram). Full inventory: [TAKAN_EVENTS.md](TAKAN_EVENTS.md).
